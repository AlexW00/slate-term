## Second slice: own-plugin settings

Implemented `plugins.settings.get/patch`, typed `plugins settings get/patch` CLI and own-namespace `workspace.pluginSettings` page wrappers. Patches use bounded literal paths, explicit delete, subtree replacement, whole-source optimistic revisions and shared save/apply/error handling. All writers now share the same source lexer, accept nested/array tables, preserve unrelated semantics/comments, and fail closed on unsupported grammar. Batch insertion and a 1 MiB source/output bound prevent pathological repeated dotted-key expansion. Own-page failures omit raw diagnostics from unrelated namespaces; directed value-free settings notifications retain their existing isolation.

Test-first editor cases were observed red then green. Independent review confirmed three issues, now fixed with regressions: multiline strings nested in arrays masquerading as application assignments; deletion of the last dotted child losing its empty parent; and overly broad old-host rejection during new guard negotiation. The CLI now uses explicit guard advertisements with a narrowly defined fallback for the first versioned API's five existing guards—never for new guards. A read-only follow-up review found no actionable findings, while requesting fresh runtime checks and more page-bridge failure coverage.

Added unit coverage for wide/nested-array settings, plus real CLI/bridge gates for conflict/no-write behavior, subsequent native Settings edits, namespace/event isolation, source removal, and typed/private errors. An integration-only, one-shot prepared-save fault injects an apply rejection after persistence, optionally simulating an external edit that rollback must preserve. Both administrative and own-page cases are covered by fixtures. This does not claim atomic rollback of arbitrary external renderer/process side effects.

Actual checks: **141 Swift tests passed** (81 core, 8 IPC, 52 settings); fresh native app/CLI build; guard-negotiation, plugin-settings, API-context and application-settings production gates passed sequentially, including administrative and page post-write rollback/external-edit cases; `git diff --check` passed. Control-Command-N is configurable and legacy command descriptors decode without the new control/contract fields. Interface details are in `docs/layout-api.md`.

Initial fresh production layout/CLI/window/tab scenarios passed, then exposed automatic bridge `scope` injection conflicting with strict mutation arguments. Legacy pane movement, app, API-context and own-plugin-settings gates passed sequentially. ### Phase 3b design and pure foundations (not yet integrated)

`docs/semantic-events-design.md` refines the approved lifecycle phase. Two read-only reviews requested concrete divider descendant semantics, an explicit model/revision/journal boundary instead of observation-at-persistence, preflighted byte bounds, per-document versus administrative delivery audiences, token-pool/admission contracts, same-connection capability negotiation, whole-envelope settings privacy, and precise command/settings lifecycle outcomes. The design now records those decisions and associated acceptance fixtures. This is not evidence of implemented semantic events, causation, or rate enforcement.

Pure `OperationAdmission.swift` foundations now provide immutable lineage, epoch/document-bound delivery references, bounded retention/depth, and aggregated integer-credit admission buckets. Ten focused tests pass, including foreign audiences, expiry/replay/fan-out, collision/overflow boundaries, exact refill, denial atomicity, identity churn and recovery exemptions. A scoped read-only review found no confirmed defects; requested boundary cases were added. These helpers are **not wired into host dispatch or event delivery** yet.

A production CLI mock reproduced capability discovery and guarded dispatch using separate peers. The new scoped `UnixClient.withSession` keeps negotiation and dispatch on one handshaken connection, closes on scope exit/transport error, and never reconnects implicitly. IPC lifetime tests and replacement-peer negotiation coverage were added. Follow-up coverage reproduced another failure: malformed JSON returned after a dispatched mutation was reported as `outcome: rejected`. Response framing/decoding failures now become transport errors with `outcome: unknown`, without raw decoder diagnostics. **164 Swift tests passed** (100 core, 12 IPC, 52 settings), followed by a fresh app/CLI build and negotiation, API-context, own-plugin-settings and expanded layout gates sequentially; `git diff --check` passed. Evidence: `operation-{admission,connection,response}-red.log`, `operation-admission-green.log`, `operation-foundation-{unit,build}.log`, `operation-connection-green.log`, and `operation-{context,plugin-settings,layout}-regression.log`.
