# Phase 3b implementation design (not yet delivered)

This refines the approved [event plan](api-extension-plan.md#6-semantic-events-and-causation). It is an implementation proposal for review, not a capability advertisement. No veto/interception hooks.

## Operation boundary

- Introduce a host-issued operation ID and native-assigned origin: administrative socket, registered page (bound plugin/instance/view), or native action/observation. Do not infer provenance from claimed environment or request fields.
- A synchronous workspace commit records validated intent, pre/post workspace and affected-layout revisions, affected identities and outcome. Model validation/admission and resource preparation precede assignment. Preserve existing cleanup and destructive-consent behavior.
- New mutation results include operation ID and outcome (`committed` or `unchanged`), alongside existing IDs/revisions. Preserve legacy raw reads, null results and contributed command values; do not wrap arbitrary results or overwrite user output.
- Autosave failure is separate from in-memory acceptance. Report persistence status without undoing committed live state. Shell startup, terminal input, WebKit actions and filesystem effects are not a transaction.
- Pass immutable operation context explicitly from socket/page/native adapters into shared operations; forwarding a page call through `callAsync` must not relabel it as a socket request. Async jobs retain their own immutable correlation context, not a global value held across `await`.
- Drain pending native observations under their own contexts before validating request guards. Replace observation-at-persistence with an explicit before/candidate commit: preflight bounded canonical events against a journal candidate, then assign model, revisions and journal in one non-suspending section. Persistence follows separately. A snapshot sees either side with its corresponding cursor. Delayed callbacks carry generation guards and must not consume unrelated changes under an old context.
- Audit reentrancy: native focus/layout callbacks during reconciliation are already suppressed. Native editor completion or an AppKit nested run loop must not cause a nested publisher to consume the outer operation's changes. Queue captured native callbacks or reject reentrant admission; do not spin a run loop while committing.

## Canonical events

Preserve compatibility topics, including `host.workspace.changed`. Enrich rather than duplicate existing pane-created/type/title/closed events.

- Split: one `host.pane.created`, with normalized split intent (leaf/root, edge, type, new-pane fraction, focus policy), followed by applicable layout/focus/compatibility notifications.
- Pane move: one `host.pane.moved` for the known source, with destination and edge, followed by applicable layout/focus/compatibility notifications.
- Resize/equalize: bounded `host.layout.resized` facts addressing changed split paths; no entire layout in payloads.
- Tab membership change: `host.tab.moved` for each existing tab whose group changed. Within one group, `host.tab.reordered` describes each changed final index, including displaced neighbors. This definition is deterministic for native observations without inventing which tab the user dragged.
- Creation/closure facts use stable identities. Define and test deterministic ordering, with pane closure before owning-tab closure and tab creation before contained-pane creation.
- Contributed command jobs emit `host.command.started` at admitted invocation creation, before spawn, and exactly one `host.command.finished` for success, spawn failure, timeout or cancellation. Store captured context on the run and emit typed lifecycle records directly, not by interpreting UI `onChange` callbacks or copying `run.info`. Include bounded state/exit/cancellation facts, not arguments, stdout, stderr or arbitrary failure messages. Finish owned jobs before journal closure where possible; shutdown delivery is not guaranteed. Completion does not imply rollback of partial external effects.
- Settings have a distinct boundary: preflight possible allowlisted facts before persistence, then publish a success fact only after successful runtime application. Source-only changes emit a separately identified source-revision fact, not an applied-settings change. On apply/rollback failure, publish only observed applied-state transitions and a bounded failure outcome with `persisted`/source-validity/match state when known; never invent success or atomic filesystem rollback. Reserve journal publication capacity/encoding before writing and keep any intervening external edit explicit in the operation result.
- Separate internal operation context from audience-safe event projection. Host topics retain `source: host`; permitted initiating-origin facts are separate. Own-settings details remain directed. Global settings envelopes omit namespace paths, plugin/instance/view/pane identifiers identifying the caller, private parent-event details and specific private intents; retain only safe opaque correlation and public revision facts. Test the entire delivered envelope, not just its payload.
- No-op commands do not emit fabricated lifecycle changes. Existing journal expiry/restart and subscribe-after-snapshot recovery remain authoritative.

## Native divider handling

A divider drag has explicit begin/end boundaries, local visual preview and one shared guarded resize commit. Preserve descendant **model fractions**, reapplying them during preview; constrain the dragged divider with the same recursive 80-point leaf minimum calculation used by the API. Do not import incidental descendant autoresize callbacks as separate semantic mutations. Capture controller generation, tab, path and layout revision at start. Mark geometry unavailable for the entire affected tab during preview.

On normal completion, commit through the shared resize operation. Cancellation restores current authoritative fractions without changing the model. Before a competing mutation, finish the valid pending gesture (or cancel an obsolete one), then validate the competing request against the resulting revisions. A detached/superseded controller cannot complete its old gesture. Allow at most one backing pixel of rendering-rounding discrepancy; never admit a leaf below the native minimum. Ordinary window/tab presentation resizing preserves fractions where feasible; genuine constrained adjustments require a separately attributed native observation, not a fabricated user drag. Initialization callbacks are not mutations. Nested-divider/API conformance must verify both model and rendered geometry.

## Causation and admission

- Causation is optional transport metadata, separate from command arguments. Do not retroactively reserve an arbitrary contributed-command parameter such as `cause`.
- Event delivery can include an opaque random host-issued reference. Page audience is app epoch + registration identity + logical instance + view + bridge-document generation, revalidated immediately before mutation after suspension. This is separate from existing logical-instance event routing. Administrative audience is same-user administrative access within the app epoch/expiry, **not** a socket connection or authenticated process: the CLI opens a new connection for each invocation.
- References are not bridge authentication tokens or public document IDs. Reject forged, expired and foreign-audience references before mutation; never silently downgrade to a root request. References are reusable for sibling work: siblings share parent depth; replay preserves stored lineage rather than resetting it. Accepted async work retains immutable lineage after reference expiry.
- Provisional bounds: 4096 references globally, 256 per audience, maximum TTL five minutes, causal depth eight. Earlier capacity eviction is permitted and yields typed recovery, not a guaranteed five-minute lease. Store bounded lineage facts with retained events; do not retain unbounded ancestor chains. Pure tests inject clock/token generation and exercise fan-out/replay/eviction.
- Use monotonic token buckets aggregated by host-bound plugin ID across all its instances/views/documents: provisional refill 10 mutations/second with burst 20; global automation refill 100/second with burst 100. Administrative roots consume the global bucket too. Measure these defaults under fan-out and main-thread responsiveness tests before finalizing.
- Count each admitted side-effecting request once across direct/indirect dispatch: workspace mutations, terminal input/run, web mutations, storage/settings writes, custom event emission and command launch. Successful no-ops are not refunded. Reads/recovery are not charged. Native user actions and an explicit allowlist of cancel/stop/disable controls remain available; an arbitrary command string does not confer exemption.
- Expose typed refusal with bounded retry/recovery data. Generic administrators may start independent roots but cannot evade the global budget. This is accidental-loop containment, not a sandbox against trusted local code.
- Page event handlers should pass delivery context explicitly for asynchronous work. Do not keep a global implicit cause active across arbitrary awaits and misattribute unrelated user input. Indirect DOM effects may be independent roots when causation cannot be proved.
- Command processes must not gain attributed provenance merely by claiming an invocation ID. Authenticated process-session integration belongs with the separately reviewed service protocol unless a bounded, reviewed earlier adapter is necessary.

## Bounds and compatibility

Reserve 128 bytes per event for delivery metadata during journal admission and batching, keeping delivered events within 16 KiB and batches within 512 KiB. This reduces the available custom payload budget; document the change and reject oversized publication before sequence allocation/eviction. Required canonical facts are preflighted before model assignment, emitted as bounded individual records (one split path or affected identity per fact), never logged-and-dropped after commit. Events from one operation can span polls; journal retention may still expire old cursors. Preserve scan progress for empty/nonmatching polls and never skip an unreturned match.

Use a typed, versioned request-metadata envelope outside `params` in IPC and both bridge worlds. SDK example: `workspace.command(id, params, {cause: event.deliveryContext})`; give mutation helpers equivalent final options without dropping cancellation. Reject unknown/malformed metadata. Advertise a versioned causation capability. CLI discovery and guarded/context-bearing dispatch must use the **same connection**, with no reconnect fallback, so replacement by an older host cannot silently ignore metadata. Preserve existing guard-support rules while closing this connection-level race. Ordinary pages/subframes receive no bridge; administrative exclusions remain enforced indirectly too.

## Fact schema constraints

Every semantic fact includes operation ID, action kind, pre/post workspace revision, relevant pre/post layout revisions (null for absent/deleted tabs), and audience-safe origin/causation. Command start/finish share the invocation's operation ID and immutable lineage, but each lifecycle-only publication uses equal pre/post revisions sampled at that publication. Optional `launchWorkspaceRevision`/`launchLayoutRevision` are separately named; never describe unrelated intervening changes as the command's mutation range. If the captured target has closed, retain its historical target ID with null current layout revision and an explicit unavailable-target flag. IDs are bounded; affected-ID summaries cap at 64 with total/truncation metadata. Never copy arbitrary request dictionaries.

Specific facts: split `{paneId, tabId, anchor, targetKind, direction, type, newPaneFraction, focus}`; move `{paneId, tabId, destinationPaneId, direction}`; resize `{tabId, path, beforeFraction, afterFraction}`; tab move `{tabId, beforeGroupId, afterGroupId, beforeIndex, afterIndex}`; reorder `{tabId, groupId, beforeIndex, afterIndex}`; title `{paneId, hasManualTitle}`; job `{invocationId, commandId, state, exitCode?, terminationReason?}`. No literal titles/settings/command input are added by these facts.

Canonical ordering: pane closures, tab closures, tab creations, pane creation/type/title, pane moves, split-path resizes, tab moves/reorders, then generic layout/focus/group/workspace compatibility notifications. Within categories use stable model order and deterministic split-path traversal. Golden fixtures must cover normalized legacy aliases, displaced tabs, deleted revisions and no-ops.

## Acceptance work

1. Pure tests: canonical event ordering/no-ops, normalized intent, privacy, bounded facts, token forgery/audience/expiry/depth, admission independence and recovery, byte-bound cursor behavior.
2. Host/CLI/page tests: same operation results/events, immutable captured targets, async guard revalidation, explicit causal chains and loops refused without mutation.
3. Native tests: menu/header/shortcut operations, divider commit versus pixels, stale controllers, tab-group observation, responder behavior and native reentrancy.
4. Real command success/spawn-failure/cancellation/timeout completion, including unrelated workspace changes and target deletion before completion; settings source-only/apply/rollback/external-edit outcomes; no private output or settings values in lifecycle envelopes.
5. Existing event replay/extension interoperability gates, plus source/binary-aligned full verification after the remaining roadmap is integrated.
