    Range

    From a side panel to a full app.

    Start with a panel next to your shell. Put a face on a script. Let a bigger idea take over the window.

    01

    A panel beside your agents

    Track sessions, queue the next task, and see which agent needs you, without leaving the terminals they run in.

    02

    An interface for a script

    Give a command-line workflow inputs, a Run button, and a results table. The script stays the same; using it gets easier.

    03

    An app that takes the stage

    Build an experiment workbench. Compare runs, inspect results, and keep a terminal close by for when you need it.

    Proposed examples to show what’s possible. They don’t ship with Slate.

    Foundation

    A great terminal first.

    A blank slate, not a blank start. Slate is a native macOS terminal that’s useful before you extend anything.

    • Powered by libghosttyReal Ghostty terminal surfaces in native AppKit windows.
    • Tabs, splits, zoomNested panes, directional focus, and zoom for the one that matters.
    • ⌘K command pickerFuzzy search across every command, in native Liquid Glass.
    • Browser panesPreview a site or read the docs next to your shell.
    • Themes & TOML settingsFonts, themes, and shortcuts reload live as you edit.
    • Saved layoutsSave an arrangement and open it again from a Spotlight launcher.

    How it works

    Your agents build. Slate connects the pieces.

    A plugin system and CLI give you and your agents a direct way to add panels, commands, and interfaces, right where you already work.

    Plugins

    Panels, commands, header buttons, and background services. Plugins are trusted code you register, with settings and storage of their own.

    The CLI

    slate-term registers plugins, splits and arranges panes, reads the workspace, and saves layouts. Anything that can run a shell command can use it.

    Your agents

    Bring Claude Code, Codex, or another command-line agent. Slate doesn’t include a model. A Slate skill teaches your agent the API.

      what your agent runsillustrative · flags abbreviated
    # Register the plugin it just wrote, then place its panel
$ slate-term plugins register --manifest ~/slate/pr-board/plugin.json
$ slate-term panes split --pane p1 --right --type pr-board
$ slate-term panes set-title --pane p1 --title 'Agent'

# Change it, reload it, keep working
$ slate-term plugins restart pr-board

# Save the arrangement and open it later from Spotlight
$ slate-term layouts capture --window W1 --name 'Release day'
$ slate-term layouts launcher --id ID --path ~/Applications/Release\ day.app

    Iteration

    Build. Use. Refine.

    Your first version is a starting point. Trying an idea, using it, and changing it stays one short loop.

    01

    Build

    Describe what’s missing. Your agent writes a plugin and puts it in a pane.

    02

    Use

    Try it on the real task, beside the terminal you were already using.

    03

    Refine

    Ask for what’s missing. Keep what works. Repeat as your needs change.

    And back to the start, whenever you like.
