    02Range

    A small panel. A front end. A whole app.

    Keep a tool beside the terminal, or give it the room to become the focus of your workspace. Three examples of the shapes it can take.

    beside your agents

    An agent-workflow panel

    Agents work in your terminals. A panel next to them shows what each one is doing, what needs your review and what's finished.

    for a script you run often

    A visual interface for a script

    Give a command-line workflow inputs, a run button and results you can see. The script stays the same. Now it's easier to use.

    when it outgrows a sidebar

    A larger plugin app

    An experiment workbench that compares runs and charts results, with a terminal underneath. It grows as you learn what you need.

    Proposed examples to build and record. They don't ship with Slate.

    03The loop

    Build it. Use it. Ask for changes.

    The first version is a starting point. Use it on real work, notice what's missing, and ask your agent to change it in the same place you use it.

    04Foundation

    A real terminal before anything else.

    Slate is a native macOS terminal built on libghostty. It's useful the day you open it, before you add a single panel. Everything you build later sits on that foundation.

    • 01Ghostty-powered panes in native AppKit windows

    • 03⌘K command picker for built-in and plugin commands
    • 04Browser panes next to your terminals
    • 05TOML settings and themes that reload live
    • 06Saved layouts you can open from a Spotlight launcher

    05How it works

    Plugins, a CLI, and your agents.

    Slate provides the parts. Your agents use them to put tools together, right where you work.

    Plugins

    Plugins add panels, commands and background services. A panel is a web view with a bridge to your workspace. Plugins are trusted code you choose to run.

    The CLI

    slate-term registers plugins, runs commands, arranges panes and saves layouts. Anything that can run a shell command can use it.

    Your agents

    Your agents run in Slate's terminals, as they do in any terminal. The Slate skill shows them the API, so they can build a tool and wire it in.

    ILLUSTRATIVE 
    # what an agent might run after writing a plugin
$ slate-term plugins validate ./reading-list
$ slate-term plugins register ./reading-list
$ slate-term command list
$ slate-term command run reading-list.open

# keep the arrangement, open it from Spotlight
$ slate-term layouts capture "Side project"
$ slate-term layouts launcher "Side project"

    The panel is a plugin. The plumbing is the CLI.

    Save a layout and Slate can create a local launcher for it. Type its name in Spotlight and your workspace opens, panels and all.

    Launchers open saved layouts in Slate. They aren't standalone apps.

    06Agents

    Bring your own agents.

    Slate doesn't include a model or a chat window. You bring the coding agents you already use, and they run in a Slate terminal like any other command.

    What changes is what they can reach. With the CLI and the Slate skill, an agent can build a panel, open it next to you and update it when you ask.
