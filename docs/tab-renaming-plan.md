# Tab renaming implementation plan

Status: proposed; independently reviewed and reconciled. No feature implementation.

## Goal and boundaries

Let users rename live tabs through native UI and the shared trusted API, with CLI, registered-page and service parity. Names belong to stable tab identities and survive restoration, rearrangement and pane changes. Implement once in the authoritative model; native UI is a client of that operation.

Do not replace AppKit's tab bar, invent dynamic process-derived tab titles, change pane naming, rename tab/group IDs, or ship/deploy anything. Preserve the existing uncommitted tab-overview work (`Native/WorkspaceWindow.swift`, its host extraction, tests and build wiring). This document is the only change made for planning.

## Repository findings

- `Sources/SlateTermCore/Workspace.swift`: `Tab` has identity, layout, focus/zoom and terminal history, but no name. `Workspace.resolvedTab(pane:tab:)` validates ownership and resolves current membership; workspace snapshots encode tabs directly.
- `Native/WorkspaceHost.swift`: reconciliation creates one `WorkspaceWindow` per tab, sets every window title to `Slate Terminal`, and uses native AppKit tab groups. `tabs.list` encodes `workspace.tabs`. Pane titles do not currently change window titles.
- Existing pane naming spans `Workspace.setManualTitle`, `CommandRegistry`, `CommandContract`, `WorkspaceMutationCommand`, the host's metadata-only commit path, `PaneContainer`'s explicit-confirmation popover, and `PluginPane`'s `workspace.panes.setTitle/clearTitle` helpers.
- `APIFoundation.swift` and `WorkspaceTransition.swift` derive revisions and bounded post-commit facts from before/after model values. Title-only changes should not be topology revisions.
- `Native/WorkspaceAPI.swift` constructs revisioned tab inspection separately from Codable tabs. `Native/LayoutAPI.swift` separately constructs native-window inspection. Both need explicit title projection.
- `Sources/SlateTermCLI/LayoutCLI.swift` owns `Tabs`; `SlateTermCLI.swift` owns shared `Target` routing and safety guards. Explicit `--tab` suppresses inherited pane/session defaults.
- `SavedLayoutTab.name` is currently an editor label, not a live title (`docs/saved-layouts.md`). `SavedLayoutFields.swift` deliberately renumbers conventional `Tab N` labels after recipe editing. Capture currently synthesizes `Tab N`; opening ignores `name`. Do not silently reinterpret those existing labels as manual live titles.

## Proposed behavior

### Naming semantics

1. Add optional `Tab.manualTitle`, default nil. Effective title is `manualTitle ?? "Slate Terminal"`; clearing preserves today's default. No automatic derivation from a focused pane, process, directory or document.
2. Trim surrounding whitespace/newlines; empty/whitespace-only input clears the override. Preserve interior spacing, case and Unicode literally. Permit duplicates, including names equal to the default or `Tab N`; never infer identity or automatic/manual provenance from text.
3. Bound normalized names to 100 Swift characters and 1024 UTF-8 bytes, with no remaining `CharacterSet.controlCharacters` scalars. These match saved-layout name limits, avoiding lossy capture. Reject, never truncate. Document that these tab limits differ from existing 4096-byte manual pane titles. Invalid API input is `-32602`.
4. Store canonical values. On workspace restore, missing/null means nil; a wrong JSON type or invalid/noncanonical non-null title rejects the snapshot through existing recovery behavior. No migration framework or workspace schema bump for this unreleased optional field.
5. Rename/clear never changes key tab, pane focus, layout/zoom, group membership, native window identity, terminal sessions or plugin lifetimes. Names follow TabID through reorder/move/detach. New ordinary tabs start unnamed; closing deletes the name with the tab.
6. Repeating the same normalized value (including repeated clear) is unchanged: no revision advance or events. Retain the existing metadata-command save attempt even on a no-op: an explicit repeated setter can persist live state after an earlier failed save.

### Public API and adapters

Use the existing `command.run` route, not a second top-level rename RPC:

```json
{"id":"tab.title.set","tab":"t2","title":"Build","expectedWorkspaceRevision":"REV"}
{"id":"tab.title.clear","tab":"t2"}
```

- Register `tab.title.set` (required string `title`), `tab.title.clear` (no payload), and `tab.rename` (opens native editor; no payload, no default shortcut). `tab.rename` is the UI/picker action, not the programmatic title setter.
- Extend `CommandRegistry`, `CommandContract` and `WorkspaceMutationCommand.ids`; call one model mutator, e.g. `Workspace.setManualTabTitle(_:for:)`. Enforce known payload keys/types. Missing/null/non-string `title`, unsupported guards and unknown payload keys fail closed.
- Resolve targets through existing shared defaults/`resolvedTab`: explicit tab wins over inherited defaults; pane-only targets its live owning tab; supplied pane+tab must agree; a targetless native/root call uses the key tab. Stale explicit/inherited identities must fail, never fall back to focus. Registered-page and service callers retain existing bound caller-liveness validation.
- Preserve optional instance, anchor-session, workspace and layout guards under existing rules. No new mandatory revision guard: this is metadata, like pane titles. `expectedWorkspaceRevision` is the optimistic concurrency guard for names; layout guards do not protect names. Web/document/source/saved-layout guards remain unsupported. No automatic retries.
- Result: `{tabId, manualTitle: string|null, title: string, layoutRevision, operationId, outcome, workspaceRevision, workspacePersistence}`. For `tab.rename`, return `{tabId, editing:true}` after opening; that acknowledges the editor, not a committed rename.
- Add CLI `tabs set-title --tab t2 --title Build` and `tabs clear-title --tab t2`; retain normal `--pane`, inherited targets, `--active`, `--cause`, and optional guard options. Reject `--title` for other actions and reject rearrangement-only flags for title actions. The existing generic `command run tab.rename` opens the UI; a separate typed interactive CLI alias is unnecessary.
- Add registered-page `workspace.tabs.setTitle(title, params={}, options={})` and `clearTitle(params={}, options={})`, mirroring pane helpers, including final `{signal,cause}`. Services invoke the same commands through their existing shared endpoint/CLI; no service-only dispatch or allowlist.
- Extend command discovery and add `api.describe.tabTitle` metadata documenting defaults, normalization/limits, commands, state fields, event, persistence and unchanged layout revision. Existing `AutomationMethod.commandRun` already supplies transport/catalog parity; do not add redundant method enum cases.
- Expose optional `manualTitle` through encoded `tabs.list`/legacy `workspace.get`. Add both full bounded `manualTitle` and effective `title` to `workspace.snapshot.tabs`; add effective `title` to `window.list/get`. Derive all effective titles through one core helper, also used by native rendering. Do not change unrelated legacy shapes or pane title fields.

### Native UI

- Add **Rename Tab…** and **Reset Tab Name** (`tab.title.clear`) to Workspace → Tabs; include both in Cmd-K, and in configurable shortcuts with no default binding. Set-title requires arguments and stays out of the picker. Reset is available only when the captured tab has an override; rename requires a live selected, visible, non-minimized workspace window with no conflicting sheet or active application-modal dialog (`NSApp.modalWindow`). Reject unavailable editor requests with `APIError.unavailable`; metadata set/clear remains noninteractive.
- Use a small asynchronous AppKit sheet owned by the target window, not `runModal`, private tab-bar traversal or a custom tab strip. Include a `LiteralTextField`, accessible label “Tab name”, hint “Leave empty to use Slate Terminal”, Cancel and Rename. Prefill the manual name (empty with default placeholder if unnamed), select it, and support Return/Rename, Escape/Cancel and standard clipboard/IME behavior. No double-click/tab-context-menu hook is required for this first version.
- Freeze TabID, owning window identity and original manual title before presenting. Draft typing produces no model mutation. Window closure, app deactivation, selecting another tab, window reparenting/group changes or editor cancellation discard the draft. Keep one editor per window and reuse/select its field on repeated invocation for that same target; its own sheet is not a conflict. UI command availability and actual dispatch must use one admission predicate covering visibility, selection, other sheets and application-modal dialogs. Existing close/browser confirmations use `runModal`, so checking `attachedSheet` alone is insufficient.
- Commit via the shared `tab.title.set` operation, attributed as a new **native** operation even if an API client opened the editor. Revalidate target/window and original manual title immediately before preparing the transition; if another client renamed it meanwhile, show a conflict instead of overwriting. Do not bind the editor to the initiating request's lifetime or use an old whole-workspace revision that would reject unrelated pane/focus updates. No fallback to the now-focused tab and no nested mutation during native reconciliation.
- Keep invalid input visible with an inline error and no mutation. On successful commit/cancel restore valid prior focus only if the owner is still the selected active workspace window; lifecycle cancellation must not reselect/reveal the former target. An API setter on an inactive/minimized tab must remain noninteractive and must not select/reveal it.

### Commit, render, persistence and events

- Follow the host's metadata-only pane-title path: prepare `WorkspaceTransition.command`, preflight/commit model+revision+events with `commitWorkspace`, update only the affected native window title, then `persistWorkspace` and `operationResult`. Do not route title commands through general `reconcile`, which can make the key window front and alter responder state.
- Apply the same effective title when initially creating/restoring windows and on subsequent reconciliation; do not leave the existing unconditional creation default as the sole source. Use `NSWindow.title` for native tabs, overview and Window-menu labels, retaining existing native tab identifiers and overview behavior.
- Update `WorkspaceRevisions.observe` to detect changed existing tab overrides, and `WorkspaceTransition` to publish `host.tab.title.changed` plus tab-local `host.workspace.changed`. Include `tabId`, `hasManualTitle`, operation/action/origin and before/after workspace/layout revisions; never include literal names. Rename advances workspace revision only, with no invented layout/focus/reorder/group facts. Creation remains `host.tab.created`, not a redundant rename fact.
- Autosave failures keep committed live state/events and report existing `workspacePersistence` outcomes. Always retain the existing metadata-path `persistWorkspace` attempt, including unchanged setters/clears, and report its actual status. `scripts/verify-workspace-persistence.py` explicitly relies on a no-op setter recovering a failed save; do not add dirty-state tracking or skipped-save statuses for this feature.

### Saved-layout round trip without changing editor-label semantics

- Add optional `SavedLayoutTab.manualTitle`, default nil. Recipe data follows the workspace-snapshot contract rather than setter coercion: missing/null → nil; a non-null string must already be nonempty, trimmed, within both limits and free of controls. Reject empty/whitespace-only, padded, wrong-type, oversized or otherwise invalid values rather than silently normalizing files. Apply the same rule to programmatically constructed definitions during `validated()`. Include it in strict allowed keys/Codable and validate before opening resources. `name` stays a required editor label; do not change conventional-label renumbering or infer live titles from `name`.
- Capture the live override explicitly alongside the existing synthesized `Tab N` label; opening applies the optional override to fresh TabIDs in the candidate workspace before commit. Existing recipes lacking it continue opening unnamed live tabs, exactly as now. Capture/open must preserve a literal manual name such as `Tab 2` even if recipe labels later renumber.
- Recipe editing must preserve this field through selection, add/remove/reorder, save/revert, and pane edits. No new recipe-title editing UI is required; existing live rename and API cover the request. Document the field and editor-label distinction, and that older strict readers may reject it; no downgrade migration is required for unreleased formats.

## Implementation sequence and checks

1. **Core model/contracts first.** Add the optional field and shared validation/effective-title helper; implement mutation and command adapters. Extend `WorkspaceMutationTests`, `WorkspaceTests`/invariants, `APIFoundationTests` and `WorkspaceTransitionTests`. Cover Unicode/emoji/combining-character byte and character boundaries, trimming, internal controls, duplicate/default-looking names, blank clear, wrong types, unknown keys, atomic failure, ownership mismatch, stale/missing targets, no-op equality, topology/session preservation, and snapshot round trip/defaults/rejection.
2. **Revision/event and recipe tests.** Assert title-only workspace revision advance, stable layout revision, exact tab-local facts, correct `hasManualTitle` and absence of literal text. Extend `SavedLayoutTests`/`SavedLayoutTabTests` and settings workspace-store tests: optional-field validation, capture/open with fresh IDs, literal `Tab N` preservation independent of recipe-label renumbering, old recipe behavior, restore enabled/disabled and bad-snapshot recovery.
3. **Host and adapters.** Implement metadata-only title commit/rendering and inspection/discovery; extend CLI and page helpers. Extend `AutomationAliasesTests` with explicit command alias mappings (current namespace tests do not cover `Tabs` command aliases), argument validation, and core routing/default tests. Use existing `verify-layout-api.py`/`verify-workspace-persistence.py` patterns for production-path behavior and rejected publication atomicity. Add maximum-size title projection tests that retain 256-KiB snapshot/window envelope rejection, pagination and stale-cursor checks; never remove bounds to accommodate new fields.
4. **Native editor.** Add a focused controller, e.g. `Native/TabRenameController.swift`, and wire menus, picker keywords/context validation, shortcut settings and lifecycle cancellation in `WorkspaceHost`; add Xcode source wiring if needed. Use `LiteralTextField`'s existing text-checking policy. No app launch or UI code is part of this planning task.
5. **Focused integration gate.** Add `scripts/verify-tab-titles.py` using one isolated owned app/state/config and production APIs for mutations. Cover native menu/picker/shortcut opening and confirmed commit versus cancellation; API rename of inactive/minimized tabs without focus changes; CLI/page/service successful set/clear parity and native/administrative/plugin/service origin; stale guards/targets; no-op setter recovering a failed save without new events/revisions; opening refusal during an application-modal confirmation or another sheet; repeated invocation of the same editor; concurrent editor/API rename conflict; draft cancellation on close/deactivate/tab switch/reparent; publication failure leaves model/title/revision/journal unchanged; persistence status/failure and restart restoration; saved-recipe capture/open. Debug helpers may inspect/drive the native editor, never become production mutation APIs. Extend existing overview fixture to verify renamed labels without losing toggle/Escape/selection behavior; do not duplicate or overwrite its pending work.
6. **Verification/docs.** Run `swift test`, build the Debug app, then the focused native/API gates sequentially; request approval before a long window-heavy full suite. Add the new gate and all source dependencies to `scripts/verify-all.sh`/its verification manifest and document `docs/verification.md`. Capture app-owned light/dark editor and renamed native-tab/overview states, long Unicode names and single-tab windows; obtain independent rendered review during implementation. Record VoiceOver/IME/fullscreen/multi-display checks not actually executed. Update `docs/control.md`, `docs/layout-api.md`, `docs/command-picker.md`, `docs/configuration.md`, `docs/events.md`, `docs/plugins.md`, `docs/saved-layouts.md`, the shipped agent skill's relevant API references and `docs/api-extension-progress.md` with implemented/tested/deferred status.

Acceptance is not merely command registration: UI and all trusted clients must use the same model operation, names must remain readable/restorable, native tab presentation must update without content recreation/focus changes, and no-op/rejected/cancelled work must not fabricate revisions or facts.

## Independent review

A separate read-only `reviewer` agent checked this plan against repository code and contracts. It identified two actionable P2 findings; both were verified and incorporated:

- **No-op save recovery:** the original draft proposed avoiding no-op writes, conflicting with the explicit failed-save recovery contract in `scripts/verify-workspace-persistence.py:28–34` and `Native/ApplicationSettings.swift:98–102`. The plan now keeps existing save attempts/statuses and adds recovery coverage.
- **Application-modal admission:** a no-conflicting-sheet check would miss `runConfirmationAlert`'s `runModal` dialogs in `Native/WorkspaceHost.swift`. The plan now rejects opening during app-modal dialogs and shares admission logic between UI and dispatch, while allowing reuse of its own sheet.

The review also requested explicit recipe null/blank/canonicalization rules and maximum-size inspection coverage; both are now specified. It found the shared routing/guards, metadata-only revision/event flow and separate recipe/live-title semantics consistent with inspected code. These were plan corrections, not implementation fixes; the revised plan has not received a second independent review.

No implementation tests, builds or GUI checks were executed. AppKit sheet lifetime, focus, repeated invocation, concurrent rename and cancellation behavior remain implementation-time verification requirements, not verified capabilities.
